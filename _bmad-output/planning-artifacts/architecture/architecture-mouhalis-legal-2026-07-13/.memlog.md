- (decision) AD-1 Paradigm: pipes-and-filters pipeline where each stage is an idempotent filter; Notion is the blackboard/shared state coordinated by an explicit status State Machine. Prevents ad-hoc stage coupling.
- (decision) AD-2 [ADOPTED] Notion is the single System of Record (Path B). No competing store of Item truth at MVP. Prevents dual-write divergence. User-chosen.
- (decision) AD-3 Source Adapter contract: every Source (all 3 tiers) implements one interface -> yields Source Records in the unified schema. Prevents per-source output-shape drift.
- (decision) AD-4 Idempotency: ingestion keyed on source_id+source_name and SHA-256 content hash; re-runs update last_seen_at, never create duplicate Items. Prevents duplicate-on-repoll.
- (decision) AD-5 Content Class governs retention+schema: no stage may persist full text for Class B; Class C full text is staging-only under 7-day TTL. Prevents storage/PII divergence + noise.
- (decision) AD-6 State-transition ownership: pipeline performs automatic transitions only; approve/reject/reclassify are human-only. No stage may perform a human-only transition. Prevents status-field races.
- (decision) AD-7 All LLM calls route through a single metered client that writes the Cost Ledger (stage, model, tokens, usd, item_id, success). Prevents untracked/unattributable spend.
- (decision) AD-8 Config-as-data: ontology.yaml, relevance_rules.yaml, interpretation_config.yaml, sources.yaml are the single source of business rules. No hard-coded topics/rules/model-ids. Prevents logic drift between code and rules.
- (decision) AD-9 Interpretation output must validate against the pydantic schema before persist; a failing validation fails the item (alert+skip), never a partial silent record. Prevents malformed Class A records.
- (decision) AD-10 Scraping politeness is a shared middleware (rate limiter 1req/5s/domain +/-30% jitter, circuit breaker, backoff, non-identifying UA, robots.txt) used by ALL Tier-2 scrapers. Prevents each scraper mis-implementing politeness and exposing the client.
- (decision) AD-11 Downstream (Environment B) shared-data contract: pipeline must always persist class_reasoning, confidence_score, additional_sources[], external_commentary, precedent relations, and expose a B->A re-fetch entry point. Prevents breaking Cowork agents.
- (decision) AD-12 Failure isolation: every source poll and every item passes through a try-boundary; a stage failure isolates to its item/source and never halts the pipeline run. Prevents one bad item taking down a batch.
- (constraint) MVP infra is minimal: in-process scheduler (APScheduler) + local JSON/file staging + Notion. Heavyweight infra (Prefect/Postgres/Grafana) deferred to Path A / later phase.
